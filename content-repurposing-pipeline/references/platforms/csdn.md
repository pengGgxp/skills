# CSDN Platform Profile

Platform ID: `csdn`

## Position

- Purpose: searchable problem resolution and reusable technical instruction.
- Reader intent: arrive from a concrete error, configuration task, or how-to query and get a working answer.
- Best fit: error diagnosis, environment setup, deployment, API usage, and step-by-step tutorials.

## Write

- Title: include the exact technology and problem or error signature readers will search for, while remaining readable.
- Opening: state the environment, symptom, expected behavior, and verified result.
- Structure: prerequisites, reproduction, cause, solution steps, verification, alternatives, and common failure cases.
- Voice: direct, procedural, and explicit about tested versus untested conditions.
- Depth: preserve copyable commands, configuration, file locations, versions, and expected output.
- Links: use official documentation and source repositories when they improve verification.
- Ending: provide a compact diagnostic checklist rather than a generic conclusion.

## Visuals

- Use terminal, log, configuration, or UI captures only when text alone cannot show the state clearly.
- Keep commands and error text selectable in the body even when a screenshot is included.

## Avoid

- Burying the solution under a long story, omitting environment details, copying error text inaccurately, and presenting one environment as universal.
- Keyword repetition and unrelated promotional sections.

## Platform QA

- Verify that a reader can reproduce the symptom, apply the fix, and recognize success from the article alone.
- Check every command, path, version, output, and fallback condition.
