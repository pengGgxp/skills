# DEV Community Platform Profile

Platform ID: `devto`

## Position

- Purpose: practical English-language developer learning and peer discussion.
- Reader intent: build, debug, compare, or reuse a concrete engineering technique.
- Best fit: tutorials, open-source work, code walkthroughs, lessons learned, and focused technical opinions.

## Write

- Title: name the developer task, technology, or lesson in direct idiomatic English.
- Opening: state the result, prerequisites, and why the approach is useful; add a short summary when the article is long.
- Structure: problem or goal, setup, implementation, code, verification, pitfalls, alternatives, and takeaway.
- Voice: friendly developer-to-developer English, transparent about experience and uncertainty.
- Depth: include runnable snippets, tested commands, versions, expected output, and repository links.
- Links: prefer official documentation and source repositories; verify current front matter, tag, and canonical-link behavior before publishing.
- Ending: invite a specific technical comparison, correction, or extension.

## Visuals

- Prefer code as text, concise diagrams, terminal output, and authentic runtime demonstrations.
- Give GIFs and screenshots useful captions and ensure they remain legible in the article column.

## Avoid

- Literal translation, unexplained region-specific context, tag stuffing, engagement bait, untested code, and promotional product copy disguised as a tutorial.
- Claiming community consensus or production readiness without evidence.

## Platform QA

- Use an idiomatic English technical reviewer and run or inspect critical examples.
- Verify front matter, code fences, versions, links, alt text, regional context, and the boundary between experience and general guidance.
