# Juejin Platform Profile

Platform ID: `juejin`

## Position

- Purpose: practical knowledge exchange among software developers.
- Reader intent: solve a development problem, understand an implementation, or reuse a technique.
- Best fit: programming, AI engineering, tool chains, debugging, architecture, and implementation reviews.

## Write

- Title: name the technology, problem, and useful outcome without stacking trend words.
- Opening: show the developer pain or result quickly, then list the environment and what the article covers.
- Structure: context, minimal reproduction or goal, implementation, key code, verification, pitfalls, and takeaway.
- Voice: peer-to-peer, concrete, technically confident without posturing.
- Depth: retain runnable code, dependency versions, commands, design choices, and failure modes.
- Links: prefer official documentation, repositories, and reproducible examples.
- Ending: summarize the reusable engineering lesson and invite a focused technical discussion.

## Visuals

- Use architecture diagrams, terminal or IDE captures, traces, and authentic UI demonstrations where they clarify behavior.
- Keep code as text rather than screenshots unless the visual context itself matters.

## Avoid

- Trend-name stacking, unexplained code walls, unverifiable benchmarks, generic AI-generated summaries, and hiding prerequisites.
- Reframing an operational incident as a universal best practice without evidence.

## Platform QA

- Re-run or inspect critical code and commands, then verify versions, environment, expected output, and failure recovery.
- Confirm the technical conclusion follows from the demonstrated implementation.
